# 📦 Outputs

This folder contains all artifacts generated by running the experimental pipeline for **“Dataset Structure Matters.”**  
It includes figures, quantitative metrics, and logs produced during preprocessing, analysis, fine-tuning, and evaluation.

---

## 📁 Structure

```
outputs/
├── figures/
├── metrics/
```

---

## 🖼️ figures/

This directory stores all generated visualizations used for analysis and reporting.

Typical plots include:
- Instruction length distributions
- Output length distributions
- Entropy and vocabulary diversity
- Semantic clustering visualizations
- Manual evaluation score charts
- Constraint-following performance plots
- Training loss curves

> These figures are used to create the visuals in `results/`.

---

## 📊 metrics/

This directory contains CSV/JSON files with computed statistics and evaluation outputs.

Examples:
- `length_metrics.csv` — instruction/response length stats
- `lexical_instruction.csv`, `lexical_output.csv` — TTR and vocab measures
- `dataset_similarity.csv` — cross-dataset similarity
- `cluster_metrics.csv` — clustering quality and dispersion
- `summary_metrics.csv` — aggregated results
- `run_metadata.json` — configuration and run info

> These files support quantitative analysis and reproducibility.

---

## 🎯 Purpose

Artifacts in this folder are used to:
- Quantify structural properties of datasets
- Evaluate model behavior after fine-tuning
- Generate figures for the paper (`results/`)
- Enable reproducibility of experiments

---

## 🔄 How to Generate

Run the pipeline scripts:

```bash
pip install -r requirements.txt
python scripts/run_pipeline.py
```

For extended analysis:

```bash
python scripts/run_extended.py
```

Outputs will be written to:
- `outputs/figures/`
- `outputs/metrics/`

---

## ⚠️ Notes

- Files may vary depending on the configuration and dataset subset used
- Large outputs can be regenerated and may not need to be version-controlled
- Ensure the `data/` directory is populated before running the pipeline

---

## 🔬 Reproducibility

- Same configuration across datasets (TinyLLaMA + LoRA)
- Shared evaluation prompts
- Deterministic scripts where applicable
